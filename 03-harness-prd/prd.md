**How fresh must it be**

-Dashboard refreshes after every upload of new transcripts

## 02 Tools · System Capabilities

**The verb list**

The model has no tools outside of generating insights and updating the dashboard. 
 It cannot search the web, open files, write the database, edit a transcript or send anything.

What the page code does on its behalf 
- Reads the dropped file, parses its header, hashes it and checks for duplicates.
- Saves the interview.
- Builds the prompt and calls the model once.
- Checks each new quote against the new transcripts.
- Appends verified new quotes to the stored evidence. The model never rewrites old evidence.
- Computes reach, and saves the insights and a history entry.

## 03 Loop · AI Costs & Latency

**Turn ceiling and escalation**

One attempt per update 
- One update per upload batch, not one per file.
- It runs automatically after a successful upload, as requested.
-  It processes only those pending interviews, never the whole set.

When it stops and hands back to a person
- Interviews saved, message shown.
- Rate limit: message asks the person to wait a minute and press Refresh insights.
-In every case the previous insights stay current, the new interviews show as Pending, and a
person decides whether to try again.

**Latency and cost target**

Dashboard refresh should happen within one minute.

## 04 Memory · Data Requirements

**What persists, at what scope**

What persists in the shared database 
- Concept: name, description, evidence note, created date.
- Interviews: full transcript text, header fields, content hash, upload time, synthetic flag.
 -An exact duplicate or a repeated Record ID is skipped
- Current insights: takeaways, strengths, isolated feedback and priorities, each with a stable
  key and its full evidence list; the interviews included; which interviews the last update
  added; version number and time.
- Insight history: every version, with each priority's reach. Nothing is overwritten there.

How earlier evidence is preserved
Evidence is carried forward by the code. An item that is returned with its key keeps every
earlier quote and gains the verified new ones. If the model returns an empty list, nothing is
deleted. An item left out of the current insights stays in the history.

What persists only in one person's browser
- The last concept they selected. 

What the model remembers
Nothing between calls. Continuity comes only from the existing insights in the prompt. The
platform may replay an identical answer if the exact same prompt is sent again within five
minutes.

What expires
Nothing. There is no retention period and no deletion path in the page.

Who may write
- Signed-in people with Contributor access or higher. View-only people can read only.
- The page hides upload for people who cannot write.

Who may read
Follows the artifact's sharing setting, which only the owner can change. The database holds full
transcripts. All current data is synthetic. Review access and retention before real interviews
are loaded.

**Expiry and write rules**

All uploaded transcript information is maintained and continuously builds unless user deletes context themselves.

## 05 Permissions · AI Risks & Mitigations

**The permission tier**

| Side-effect class | Tier |
|---|---|
| read | auto |
| draft | auto |
| write | confirm |
| send | blocked |

**Justification**

Tiered by damage if wrong.

Without asking (low damage, reversible) 
- Parse, hash and de-duplicate a dropped file, and save it as an interview.
- Run an update after a successful upload.
- Save a new insights version and history entry. The previous version is kept.

Asks once [BUILT]
- The first Claude call in a view asks the viewer to allow it. It spends that viewer's own
  Claude usage. A decline means no update, and interviews are saved as Pending.

Needs a deliberate action from a person [BUILT]
- Adding interviews, creating a concept, pressing Refresh insights after a failure.
- Sharing and access settings. The page cannot change them.
- Publishing changes to the page.

Not possible by design [BUILT]
- Deleting or editing interviews or earlier evidence.
- Sending or sharing a recap, or pushing tasks to other tools.
- Changing the ranking rule or the evidence rules. These live in the page code.
- Reading anything outside the selected concept's data.

What the agent may say without a person's sign-off
- It may recommend actions, labeled as untested proposals, each tied to a finding.
- It must not state a consensus the evidence does not show, or infer a need nobody stated.
- It must not name participants except next to a quote. Elsewhere it uses role and company.
- Where evidence is thin (one participant), the point goes to Isolated feedback, not to a
  priority.
- When a roadmap or strategy document is provided, it may not present a priority without
  its alignment note.

## 06 Verification · AI Testing & Measurement

**The check before output ships**

The standard to clear 
Every quote appears word for word in a participant's own line, and every count shown is computed
by the page from verified quotes, never taken from the model.

Checks that run before a person sees the output 
1. Shape: takeaways and priorities must be present, or nothing is saved.
2. Quote check, for every quote:
   - quotes are verbatim and nothing is made up
   - it is found inside a single participant line of that interview (interviewer lines are
     excluded), after normalizing quote marks, dashes, spacing, case and edge punctuation;
   - it is at least 8 characters;
   - a repeat of a quote already stored is not added twice.

-Earlier evidence is carried forward by the code and is never re-written by the model.
-As new transcripts are included, the most impactful quotes must be used
-Reach: unique customers (participant plus company) with at least one verified quote, shown as
   "n of N" with a percentage. The same person in two files counts once. The page re-checks all
   stored evidence against the stored transcripts every time it draws the page.
6. Recurring rule: takeaways and strengths are shown only with 2 or more customers.
   Single-customer items move to Isolated feedback.
7. Save gate: if no quote from the new interviews verifies, nothing is saved.
8. Duplicate guard at upload: content hash and Record ID.
9. Pending flag: a banner shows when saved interviews are not yet in the insights.
10. Attribution: quote cards show name, role and company with the record and timestamp.
    Everywhere else people appear by role.

What happens when it does not clear
Unverifiable quotes are excluded and counted in a visible note. If nothing can be saved, the
previous insights stay current, new interviews show as Pending, and a person is asked to retry.

**Failure behaviour**

Abort any updates and inform user of error. Ask user to retry update to refresh dashboard.
